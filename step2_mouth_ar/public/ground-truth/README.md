# User photo reference

`annotated.jpg` and `clean.jpg` are the user's `photo_area.jpg` and
`photo_area_clean.jpg`. `mask.png` contains the binary filled annotation regions
generated by `tools/evaluate_photo_area.py` at the repository root. It is an
approximate extraction from JPEG strokes, including the documented gap repair.
The existing `ground_truth_teeth.json` is deliberately not used: its polygons
do not match these particular strokes.

`left.rgb` and `right.rgb` are 160x120 RGB uint8 crops of the clean image,
resized with OpenCV INTER_AREA by that script. These ensure the browser's
shipped-model benchmark uses the same input pixels as the offline evaluation.
They contain no ground-truth labels. Crop rectangles and evaluation cards are
defined in `src/eval/photoGroundTruth.js`. Other model input sizes and the
classical detector use the browser's image resampling.

Live comparison fits one selected photo mask to the detected lip aperture of a
completed camera prediction. Manual translation, width/height scale, rotation
and flip can adjust this transfer. It does not fit to predicted tooth pixels.
Its scores are explicitly reference overlap, not frame-specific ground-truth
accuracy. A captured comparison preserves the exact input crop and prediction;
JSON export includes both masks, alignment, detector and capture time.
Matching-photo accuracy scores remain available under Test reference photo.
The benchmark uses the chosen detector and a snapshot of its parameters in a
separate session. It does not modify weights, templates, tracking, or live output.
All unmarked card pixels count as background. No tooth IDs or color classes are
evaluated. Full-resolution masks are compared without a boundary-ignore band.

To refresh the bundled reference after rerunning the extraction, copy the two
source JPGs, generated mask, and clean RGB crops to this directory together.
